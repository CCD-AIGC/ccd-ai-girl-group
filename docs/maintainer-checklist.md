# 维护者接收检查表

以下是人工流程；不会因勾选模板而自动生效。

## 收件

- 确认选择图片/歌词正确入口，ID唯一，文件名为小写英文/数字/短横线；新提案只进入 `submissions/`。
- 只接收规范中的静态白名单文件；检查文件真实类型、大小、图像尺寸、UTF-8文本和SHA-256。
- 图片先在隔离查看环境打开；拒绝脚本、快捷方式、宏、压缩包、模型权重和可执行工作流，不运行投稿者的命令。
- 不接受 `.github/`、生产配置、工作流、脚本或管理文档的投稿方修改；需要规范改进时另开讨论。
- 删除或脱敏个人资料不是授权补救。先确认投稿者有权提交，再决定是否保留。

## 复核

- 来源作者、原始出处、改动说明、AI工具/模型、输入参考是否自有或有授权逐项确认。
- 对发布、改编、商用、再分发分别确认，未知明确写待核实，不默认同意。
- 人物轮廓与现有成员可辨；歌词能服务故事而不是只列模型能力。
- 分别记录机器格式检查、模型视觉检查、人类审图/试听；没有人审就保持待审。

## 采纳与发布

- 由维护者记录审核者（可用公开网名）、日期、结论、适用文件散列和允许用途。
- 试用或采纳不自动转为正式成员/正式发行；定稿另存到相应 `episodes/` 并关联投稿 Issue/PR。
- 先检查仓库可见性和目标使用范围。改为公开之前重新审核已有全部文件，不只审核新文件。
- `CODEOWNERS` 只声明期望审阅人，不能代替真正配置的分支规则。不要宣称此仓库已开启自动拦截、签署CLA或完成版权审查。
- 本仓库没有 CI 自动运行投稿代码；未来新增工作流需单独安全审查，特别是凭据权限和不受信任 PR。
